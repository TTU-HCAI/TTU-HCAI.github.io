# Project Scope Statement

**Project Name:** KJNdustries Warehouse Integration

## Project Purpose
This project is a two-page website for a consulting business called KJNdustries Warehouse Integration. The business focuses on helping companies connect enterprise systems, warehouse management systems, and warehouse automation technologies like robotics, conveyors, and warehouse control systems. I’m building this to apply what I’ve learned about scoping, planning, HTML, CSS, GitHub, and GitHub Pages.

## Feedback Loops
My main feedback will come from my instructor through the rubric, grades, and any comments in Canvas. I’ll also review the site myself as I build it to make sure everything is following the rubric. 

## Description
The project is a simple two page website with a shared external CSS file. The homepage will introduce the business and its services. The second page will explain the business background, the kinds of integration problems it helps solve, and the consulting approach it takes. The goal is for the site to look like a profressional small B2B consulting company.

## People Resources
This is a solo project, so I’m handling the planning, writing, coding, styling, testing, and publishing myself. My instructor is the main stakeholder.

## Desired Results
A successful project means:
- Working two page website for KJNdustries Warehouse Integration
- The homepage explains the business and its services
- An about page on the business focus and consulting approach
- Navigation works ok
- Shared CSS file used on both pages
- A clean layout with no broken links or missing files
- A public GitHub repo 

## Priorities
**Time:** 1  
**Quality:** 2  
**Budget:** 3

Time is the biggest priority because of the course deadline. Quality is next because the site still needs to feel complete and professional. Budget is last because all I have to spend is TIME :D.

## Time
The project needs to be finished within the Project 03 schedule. That includes building the two pages, styling them, testing them, organizing the repo, and publishing the final site.

## Quality
“Done” means both pages work, the navigation is correct, the styling is consistent, and the site reads like a complete website for the business. I’ll consider it complete when the repo contains all files and the live site works on GitHub Pages.

## Budget
Zero

## Exclusions
The following are out of scope:
- JavaScript beyond basic functionality
- Login systems or user accounts
- Databases or backend logic
- E-commerce or payment features
- Contact forms with real message routing
- Complex animations
- More than two HTML pages
- Third-party integrations or custom applications

## Acceptance Criteria
The project is complete when it is submitted on time, published in a public GitHub repository, includes both required HTML pages plus the shared CSS file, and presents the business in a professional way.
