# Project Retrospective

## What Went Well
One thing that went well in this project was that the scope stayed relatively focused. Defining the project early as a two page website for a warehouse integration consulting business is what I had in mind the entire time. Another positive was that the course built the skills needed for all the deliverables. By the time I got to Project 03, I had worked with HTML, CSS, GitHub Desktop, GitHub Pages, and repo organization, so the final project was more of a continuation rather than starting from scratch.

The topic choice helped. Because the business is tied to the kind of work I already do around supply chain automation and warehouse systems, it was easier to write content that felt realistic and professional. I did want to expand on a few items and refresh the styles.css to look more business oriented than my original.

## What Went Wrong
The Canvas cyberattack on Thursday, 5/7, threw me for a loop. But when I logged in Friday, 5/8, it was all resolved. Then there were a few points during the course where the instructions, submission format, or sequencing of assignments caused confusion for me. Time management was a challenge because I was balancing coursework with a demanding job and normal life responsibilities.

During the Project 03 work I ran into some issues with caching when viewing my revisions. I also had an issue with viewing the project documentation link in the README.md from GitHub. My folder name and the one listed in the README didn't match exactly.

## What I Would Do Differently Next Time
The biggest thing I would do differently is create a clean checklist for each assignment and project milestone earlier in the process. That would help me separate the actual work from the submission mechanics. I also wouldn't rely entirely on the Canvas calendar view because I learned it can be deceiving when an assignment might have more than one submission date. I would think it would've been cool to have done a micro retrospective at the end of each week instead of waiting until the end of the project to reflect. That would make it easier to go back and really specify everything I had done good and bad.

Going forward, I am definitely going to be using a lot of GitHub and version control more intentionally. Having the project in one visible place makes it easier to track progress, organize files, and keep the final product professional. Overall, this project reinforced that strong planning and a solid set of tools makes anything possible if you put your mind to it.
